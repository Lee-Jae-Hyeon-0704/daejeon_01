# 05. 참고 조직과의 비교 보고서

참고한 페이지: "영상 에이전트 팀" (디렉터 1명 + 전문 에이전트 11명이 광고 영상 프로젝트를 진행하는 구조를 설명한 HTML).
2026-11-11에 비교했고, 아래 12개 항목은 모두 현재 설계에 반영했다.

## 요약
초기 설계는 **누가 결정하고 승인하는지**는 분명했지만, **직원들이 어떻게 맥락을 넘겨받고, 무엇을 근거로 일하고, 어떻게 나아지는지**를 정하는 운영 장치가 빠져 있었다.

## 부족했던 점과 반영 내용

| # | 부족했던 점 | 참고 조직 | 반영 |
|---|---|---|---|
| 1 | 맥락 전달 구조 없음 | `handoffs/` 인수인계서 6항목, 경로 전달 | `templates/handoff.md`, 짧은 답 형식 |
| 2 | 파일·폴더 구조 없음 | 표준 폴더 11개, 폴더별 쓰기 권한, `_v2` | 표준 폴더, 직원별 쓰기 폴더, 덮어쓰기 금지 |
| 3 | 근거 체계 없음 | E·I·M ID, 4종 꼬리표, 검수 관문 | `templates/evidence.md`, 공통 규칙 1·2 |
| 4 | 검수가 한 명에게 집중 | 결과물별 지정 검토자, 3단계 판정 | 교차 검토 분산, 통과/수정 후 통과/재작업 |
| 5 | 팀 호출 규칙 없음 | 요청 유형별 경로, 호출 비용 명시 | 4가지 요청 유형 규칙 |
| 6 | 충돌 조정 방법 없음 | 디렉터가 근거 비교, `decisions.md` | `templates/decisions.md` |
| 7 | 학습 구조 없음 | `learnings.md` 한 줄, 설계 때 먼저 읽기 | `company/learnings.md` |
| 8 | 마무리 절차가 얇음 | 자기 검수 7항목, 상세 최종 보고 | 자기 검수 7항목, `templates/final-report.md` |
| 9 | 능력의 한계 미정리 | 할 수 없는 일 → 대신 하는 일 | 5개 항목 (특히 법적 판단은 "전문 검토 필요") |
| 10 | 직원 구성 빈자리 | 성과 분석, 비주얼 담당 | 비주얼 디렉터·성과 분석가 합류 예정 |
| 11 | 시뮬레이션 논리 허점 | 확정값 즉시 전달로 재작업 방지 | 제품명 확정 즉시 SNS에 전달 |
| 12 | 프로젝트 지침 층 없음 | 지침 5층 | `templates/project-CLAUDE.md` |

## 우리 설계가 더 나은 점
- 사장 승인 지점 2곳이 명시적이다
- 직급별 권한표로 누가 무엇을 못 하는지 한눈에 보인다
- 재작업 횟수 한도(2회)로 무한 반복을 막는다
- 운영 현황 대시보드(승인 대기함·직원 상태·활동 로그)가 있다
- 식품 업종에 맞춘 공통 규칙(건강 효능 암시 금지, 경쟁사 비방 금지)이 있다

## 남은 한계
참고 조직의 학습 기록은 실제 프로젝트 기록이지만, 이 저장소의 대시보드 숫자와 로그는 모두 가상이다. 시범 운영 후 실제 기록으로 교체한다.
