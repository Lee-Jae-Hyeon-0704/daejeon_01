# 01. 회사와 실습 범위

## 모델 회사: 라라스윗
공식 홈페이지(lalasweet.kr)를 텍스트로 읽고 정리한 내용이다. 사진·색감 등 시각 요소는 직접 확인하지 않았다.

- 저당·저칼로리 디저트 브랜드. 주력은 아이스크림, 운영사는 주식회사 오디너리
- 제품군: 아이스크림·빙과, 과자·제과, 쫀득바, 단백질 쉐이크 등
- 브랜드 메시지: "칼로리는 가볍게, 성분은 착하게"
- 톤: 식감과 소리로 맛을 표현하는 감각적이고 친근한 말투
- 채널: 자사몰(핵심), 인스타그램, 유튜브
- 운영 요소: 할인 특가, 멤버십, 전화·채널톡 상담, 공지·FAQ

> 실습 목적으로만 모델로 삼았다. 결과물은 라라스윗 공식 자료처럼 보이지 않게 한다.

## 실습 범위
**신제품 기획 → 출시 마케팅.** 조사·기획·카피·콘텐츠·검수가 이어져 여러 직무의 협업이 잘 드러나는 흐름이라 선택했다.

다른 후보였던 범위: 마케팅 콘텐츠만, 고객 응대(CS), 자사몰 운영, 회사 전체.

## 운영 방식: Claude Code 서브에이전트
| 방식 | 장점 | 단점 |
|---|---|---|
| Claude 프로젝트를 직원별로 | 코딩 없이 바로 시작, 직원 하나하나 체감 | 직원 간 전달을 사장이 직접 복사 |
| **Claude Code 서브에이전트 (선택)** | 비서실장이 직원을 자동 호출, 실제 멀티 에이전트 실습 | 터미널·설정 파일에 익숙해져야 함 |

선택 이유: AI 에이전트 자체에 초점을 둔 실습이기 때문.

### 이 방식이 조직 설계에 준 제약
- 서브에이전트는 서로를 부를 수 없다 → **비서실장(메인 에이전트)이 허브**
- 서브에이전트는 매번 기억 없이 시작한다 → **파일이 기억** (인수인계서)
- 서브에이전트는 사장에게 직접 묻지 못한다 → 질문은 비서실장을 거친다
- 그래서 "팀장"은 팀원을 지휘하지 않고, **동료 결과물 검토** 역할로 바뀌었다

## 인원 결정
- **5명 + 비서실장**으로 시작 (사장 결정)
- 직원을 나누는 기준: 사고방식이 다를 때 · 결과물 형식이 다를 때 · 필요한 도구가 다를 때
- 합류 예정 2명: 비주얼 디렉터, 성과 분석가 (`docs/planned-agents/`)
