# 03. 업무 흐름

## 6단계

| 단계 | 담당 | 내용 | 검토 |
|---|---|---|---|
| 0. 계획 | 비서실장 | brief 작성, learnings 읽기, 팀 설계 보고 | 사장 확인 |
| 1. 트렌드 조사 | 리서처 | 조사 + 근거 대장(E) | 기획자: 기획에 쓸 수 있는가 |
| 2. 콘셉트 제안 | 기획자 | 인사이트·메시지 + 콘셉트 2~3안, 안마다 근거 ID | 리서처(근거 일치) + 검수관(표현) |
| 3. 콘셉트 승인 | **사장** | 선택지·추천안·가장 약한 고리를 보고 선택 | — |
| 4. 카피·콘텐츠 제작 | 카피 ‖ SNS | 병렬 시작, 제품명 확정 즉시 SNS에 전달 | — |
| 5. 교차 검토·검수 | 동료 + 검수관 | 카피 ← 기획자, SNS ← 카피라이터, 대외물 ← 검수관 | 판정 3단계, 재작업 최대 2회 |
| 6. 최종 승인 | **사장** | 자기 검수 7항목을 거친 최종 보고서로 확정 | — |

## 비서실장 운영 절차
1. 접수 → `00_brief/brief.md`
2. 설계 → `company/learnings.md` 먼저 읽기, 팀 설계 보고
3. 지시문 → 6요소 (`templates/instruction.md`)
4. 인수인계 → 경로 전달, 직접 요약 금지
5. 교차 검토 → 검토자 새로 호출
6. 충돌 조정 → `00_brief/decisions.md`
7. 자기 검수 → 7항목
8. 최종 보고 → `final/final-report.md`, 승인 후 learnings 한 줄

## 언제 팀을 움직이나
| 요청 예 | 유형 | 처리 | 상대 비용 |
|---|---|---|---|
| "상세페이지 오타 하나만 고쳐줘" | 짧은 수정 | 비서실장 직접 | 낮음 |
| "카피라이터한테 제품명 5개만 더 받아줘" | 이름 지정 | 해당 직원 + 검수관 | 중간 |
| "가을 신제품도 한번 해볼까?" | 애매한 요청 | 팀 진행 제안 후 대기 | 낮음 |
| "/new-product 여름 저당 아이스바" | 팀 진행 | 6단계 시작 | 높음 |

## 충돌 조정
- 두 직원의 결과가 부딪히면 비서실장이 근거 ID를 비교해 결정한다
- 결정과 이유를 `decisions.md`에 남긴다
- 큰 방향 전환은 사장 승인
- 예: 기획자는 "맛", SNS는 "식감" 강조 → 선택 콘셉트의 핵심 근거 기준으로 "식감" 결정

## 사장 승인 지점
- 승인 1: 콘셉트 선택 — 엉뚱한 방향으로 다 만들고 버리는 일을 막는다
- 승인 2: 최종 확정
- 그 외: 방향 변경·애매한 판단·재작업 2회 초과
